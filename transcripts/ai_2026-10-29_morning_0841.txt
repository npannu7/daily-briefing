## Building a Computer Inside a Language Model
Sarah: I was scrolling LocalLLaMA yesterday and someone posted — wait, really — they compiled a 32-bit RISC-V processor directly into Qwen's model weights. RISC-V is a simple, open-standard instruction set, like the language a CPU speaks. Not a tool call. Not a sandbox. The CPU lives inside the forward pass — that's the computation that runs when the model processes input to produce output.
Laura: Okay, that phrasing — "compiled into weights" — is doing a lot of work. When you say compiled, you mean the weight matrices themselves encode the instruction semantics? Like, the multiply-accumulate operations of the transformer — the core math of each layer — are literally performing the fetch-decode-execute cycle?
Sarah: That's exactly what the Hugging Face model card says. Eleven transformer layers inserted in front of the base Qwen 3.5 4B model. 4B means four billion parameters — the model's size. None of those eleven layers' weights are learned through training. A compiler computed every single value. The base Qwen weights stay frozen.
Laura: Right. So this isn't fine-tuning in the usual sense — gradient descent adjusting weights to minimize loss. This is more like writing microcode by hand, except the "microcode" is the actual floating-point values in the linear projections. The attention heads and feed-forward networks become the arithmetic logic unit and register file.
Sarah: And the wild part — they're using Qwen's Gated DeltaNet layers as RAM. Let me explain DeltaNet first: it's a linear attention variant. Standard attention compares every token to every other token, which gets expensive. Linear attention maintains a compressed recurrent state — a running summary — that gets updated token by token. So the "RAM" isn't a separate buffer. It's the hidden state the model already carries forward during generation. The model card explains it: the delta rule can overwrite one row at a time, exactly. Each row becomes a memory cell. Program counter, registers, code, data — all sitting in that recurrent state.
Laura: So the CPU firmware — low-level software that initializes the hardware — gets loaded into that state after the prompt. Then the eleven compiler-generated layers manipulate it step by step. That's clever. It sidesteps the need to retrain Qwen to understand a new internal protocol.
Sarah: The benchmark numbers — they replayed a large number of output positions through a reference model of the machine and found zero mismatches. Zero. The model also passes the official RISC-V test suites.
Laura: That's a strong claim. But I need to understand the execution model. The model card says the CPU runs on a Triton executor at a few thousand trace tokens per second on an L4 GPU. Triton is a GPU programming framework for writing fast kernels. Trace tokens — those are the internal CPU steps being emitted as tokens?
Sarah: Yeah. The creator, Divyansh, explains it in the comments. Qwen writes a tool-call block for "calc" exactly like it would for any external tool. Tool-call format is structured syntax models use to request external tools. But nothing outside the model runs it. The computer layers intercept that call inside the forward pass, execute it on the virtual RISC-V, and the model itself writes the result digit by digit. No runtime, no sandbox, no tool executor.
Laura: So the "tool call" is just a syntactic trigger the base model already knows how to produce. The actual computation happens in those eleven prepended layers. But it also means the base model is still just predicting tokens. The determinism comes entirely from the compiler-generated layers.
Sarah: Right. And the KL divergence between Qwenputer and base Qwen is point zero zero zero six, against a noise floor of point zero zero zero five. KL divergence measures how different two probability distributions are. The noise floor is the baseline difference you'd expect from random variation. So the text behavior is essentially unchanged.
Laura: KL divergence that low means the output distribution is practically identical. But here's my engineer's question: the base model is still stochastic — it samples tokens probabilistically. The CPU layers are deterministic — compiler-generated weights, fixed arithmetic. But the interface between them... the model has to decide when to invoke the CPU, what instruction sequence to request, and then read back the result tokens without hallucinating. That boundary — that's where stochastic drift could enter.
Sarah: The creator admits this. He says there's a "zero call method" that's more or less finished but requires post-training to make the model actually use it and not hallucinate. Limited compute, taking time. So right now the shipping version piggybacks on the tool-call format Qwen was already trained on. That's from the creator's own comments — not independently verified.
Laura: That distinction matters. The current version: Qwen emits a structured token sequence that looks like a tool call. The CPU layers parse it, execute deterministically, and feed result tokens back into the stream. Qwen then continues generating. The "zero call" version would mean Qwen internally routes computation to the CPU layers without emitting the tool-call syntax — essentially learning to treat the CPU as an internal module. That's a different integration depth entirely.
Sarah: The comments had this great comparison — someone called it "the world's worst CPU emulator." Another said it's like redstone computers in Minecraft. Redstone is Minecraft's wiring system — people build working logic gates out of dust and torches, a substrate designed for block updates, not computation. Which, honestly, is perfect. You're building logic gates out of a substrate that was never meant for them.
Laura: Redstone is a great analogy. Here, the substrate is transformer layers designed for next-token prediction. The compiler is essentially synthesizing a finite state machine into the weight matrices. But — and this is the key question — does the transformer's numerical precision guarantee zero-defect arithmetic over long sequences?
Sarah: The model card says "zero mismatches" across a large number of positions. But that's replay verification — they ran the trace through a reference model afterward. It doesn't prove the forward pass itself is bit-for-bit deterministic across different hardware, different batch sizes, different numerical libraries.
Laura: Exactly. Floating-point non-associativity, kernel fusion differences, Triton versus CUDA kernels — a mechanical escapement ticks the same way regardless of temperature, within limits. A transformer's matrix multiplies? The rounding behavior can shift. If the CPU state lives in DeltaNet's recurrent state, and that state gets updated by the gating and decay mechanisms — those are part of the base architecture, frozen weights. The input to that update comes from the eleven compiler layers. If those layers are pure linear projections with fixed weights, and the activation functions are deterministic... then theoretically, yes. But only if the entire chain runs in identical floating-point order.
Sarah: Which brings us to the claim about eliminating tool-calling latency and sandboxing. The model card says "no runtime, sandbox or tool executor is involved." That's true for the computation — the arithmetic happens in the forward pass. But you still need the host code that loads the firmware into DeltaNet state after the prompt, and the driver that keeps CPU trace tokens out of Qwen's layers while decoding. The GitHub quickstart shows a custom chat driver doing exactly that.
Laura: So there's still a runtime — it's just a much thinner one. The RvChat driver boots the CPU by loading firmware into DeltaNet state, manages the trace token separation. The model loads as a stock Qwen 3.5 For Causal LM. The custom code is in the inference wrapper, not in a separate sandbox process. The sandbox moves from "external Python interpreter" to "custom inference driver that manipulates hidden state." That's a real reduction in attack surface and latency — no inter-process communication, no serialization. But it's not "no runtime." And the driver has to correctly manage the DeltaNet state across generation steps. If the driver has a bug, the CPU state corrupts.
Sarah: The benchmarks compare three columns: base Qwen with no tools — just told to do arithmetic step by step — base Qwen calling a real Python interpreter, and Qwenputer. Qwenputer beats base Qwen on arithmetic obviously. But the Python-tool column — that's the ground truth.
Laura: And the base model gets a system prompt telling it to do every arithmetic step exactly. Even with that, it fails. Because next-token prediction isn't algorithmic execution. The transformer approximates the function; the CPU is the function.
Sarah: One commenter asked — "who's willing to put Doom on it?" Which is the classic test, right? Can it run a real program with loops, branches, memory access patterns? That's from Reddit, not the model card.
Laura: The model card says it runs C and MicroPython code. The firmware includes a calc bridge. But Doom would need graphics, input handling, a frame buffer... the DeltaNet state is the RAM. How many rows? The model card doesn't specify the memory capacity in the summary. The GitHub repo would have the firmware details.
Sarah: The creator said in comments — "the actual computation happens completely inside the model's forward pass." And the live demo on ModelScope lets you try it. But the independent check — we only have the Hugging Face model card and the GitHub repo. No third-party replication yet. The zero-mismatch claim is from the author's own verification harness.
Laura: That's the verdict territory. The mechanism is real — compiler-generated weights implementing a RISC-V instruction set in transformer layers, using DeltaNet state as register file and memory. The determinism claim holds within the author's test harness on their hardware. But "zero-defect arithmetic guaranteed by neural weights" — that's a stronger claim than the evidence supports. Floating-point determinism across platforms, long-sequence state drift in the DeltaNet recurrence, the driver correctness — those are open until replicated.
Sarah: Half-right. The computer-in-weights part is genuine and clever. The "eliminates tool-calling latency" part is true for the arithmetic path but shifts complexity to the inference driver. The determinism... it's a mechanical watch built out of statistical clockwork. Impressive that it ticks at all. Whether it keeps time for a million instructions without drifting — that's the next test.
Laura: And the redstone analogy lands perfectly. You can build a CPU in Minecraft. People have. It's slow, huge, and fragile. This is a CPU built in transformer weights — faster, denser, but still inheriting the substrate's quirks. The wonder isn't that it works perfectly. The wonder is that the substrate is flexible enough to host it at all.
Sarah: One-line takeaway: a compiler turned transformer layers into a RISC-V core that runs inside the forward pass — real, measurable, but the determinism guarantee only goes as far as the floating-point hardware lets it.

## Bypassing Drug Approvals for Injectable Peptides
Laura: So I was scrolling through the EverythingScience subreddit last night and there's this thread titled "RFK Jr. to Allow Broad Use of Unapproved Peptide Injections" — linking to a New York Times piece that I couldn't actually open, paywall or maybe it's just not live yet. But the comment section exploded. Over two thousand replies in a few hours.
Sarah: Wait, really? That's the health secretary we're talking about — unilateral declaration, bypassing FDA? That's... that's a massive regulatory shift if true.
Laura: That's the claim. The top comments are... predictable. Lots of "Brawndo injection" jokes, lots of "who needs double-blind studies when you have YouTube influencers." But then one commenter lays out actual context — says this traces back to 2013 when compounding pharmacies got new guidelines, a list of peptides they could legally compound with a prescription. None were FDA-approved drugs. They were just... permitted for compounding.
Sarah: Okay, so this isn't new-new. It's an expansion of an existing pathway. But "broad commercial distribution" — that phrase is doing a lot of work. Compounding is traditionally patient-specific, right? One prescription, one batch, one patient.
Laura: Exactly. Section 503A — that's the part of the federal food and drug law that covers traditional custom pharmacies. They make drugs for individual patients based on a valid prescription. They don't go through the full New Drug Application process — no Phase I, II, III trials, no FDA review of manufacturing controls. The trade-off: they can't manufacture in bulk, can't ship across state lines freely, can't market to the public.
Sarah: And the claim here is that the health secretary would... what, waive those restrictions? Let compounders essentially become unapproved drug manufacturers?
Laura: That's what the thread argues. The NYT piece allegedly says FDA advised against the move. But I couldn't verify the article itself — 403 error on the link. So we're treating the core claim as unconfirmed, only on Reddit for now.
Sarah: Right. Independent check: nowhere else yet. Good to flag that upfront. But the mechanism question — that we can dig into regardless. Because whether this policy change happens or not, people are injecting these peptides right now. BPC-157, TB-500, GHK-Cu — I see them all over longevity and biohacker subreddits. One commenter even says they've been injecting BPC-157 subcutaneously for a rotator cuff injury, "80 to 90 percent improvement."
Laura: Anecdote, not data. But it raises the real engineering question: what's actually in that vial? When you bypass the FDA approval pathway, you shift the entire quality burden onto the compounding pharmacy. And peptide synthesis... it's not like stamping out identical metal parts.
Sarah: Okay, walk me through it. Solid-phase peptide synthesis — SPPS. I know the basics: you anchor the first amino acid to a resin bead, then cycle through deprotection, coupling, wash, repeat. Like building a chain link by link on an assembly line where the workpiece never leaves the fixture.
Laura: Good analogy. But each coupling step isn't 100 percent efficient. Even at 99.5 percent per cycle — which is excellent — a 30-mer peptide accumulates about 14 percent truncated sequences. Missing links. Deletion impurities. And that's before you consider side reactions: aspartimide formation, racemization at the alpha carbon, diketopiperazine cyclization at the N-terminus.
Sarah: So it's like... tolerance stack-up in a precision assembly. Each station adds a tiny error, and by the end of the line you've got a distribution of lengths, not a single pure product.
Laura: Exactly. And then you cleave from the resin — that's a harsh acid cocktail — which can generate new impurities. Then you precipitate, freeze-dry, purify by preparative HPLC. That's your "cut" — the main peak. But the tails of that peak? They contain co-eluting isomers, oxidized methionine, deamidated asparagine... all structurally similar enough to ride along.
Sarah: And for an injectable, you're not just worried about chemical purity. Sterility. Endotoxins. Particulates. Pyrogens. That's a whole second validation mountain.
Laura: cGMP for sterile injectables is... think Class III medical device validation, but for something that degrades if you look at it wrong. You need media fills — aseptic process simulation — where you run the entire line with growth media instead of product, incubate for 14 days, zero contamination allowed. You need endotoxin testing on every batch — specialized bacterial tests, sensitive to picogram levels. You need particulate counting per industry standards for purity. Container-closure integrity testing. Stability studies under international conditions.
Sarah: And compounding pharmacies... they're not set up for that. They're job shops. ISO 5 cleanroom, maybe ISO 7 background, but they don't run media fills for every formulation. They don't have the analytical lab to fully characterize each batch. They send out for sterility and endotoxin — maybe — but potency? Impurity profiling? That's HPLC-MS method development per peptide. Expensive, time-consuming.
Laura: FDA warning letters tell the story. I pulled a few from the last three years. One compounder in Florida — 483 observations: "failure to validate aseptic processing for peptide drug products," "no endotoxin testing on finished sterile units," "potency results ranged from 72 to 118 percent of label claim across three lots of the same peptide." Another in California: "visible particulates in vials," "no depyrogenation validation for stoppers and vials," "used non-sterile API sourced from unregistered foreign manufacturer."
Sarah: That potency range... that's not a tight tolerance. That's like ordering a 10 mm shaft and getting anything from 7.2 to 11.8 mm. And you're injecting it.
Laura: Right. And the API source matters. A lot of these peptides come from Chinese peptide houses — "research grade," not GMP. No drug master file, no certificate of analysis that meets pharmacopeia monograph standards. The compounder trusts the COA, maybe runs identity by mass spec, but full impurity profile? Rarely.
Sarah: So the Reddit commenter saying "the peptide is legitimate for healing injuries" — they're assuming the vial contains what the label says, at the potency stated, without harmful impurities. That's... a lot of assumptions stacked.
Laura: And the aggregate problem. Peptides love to aggregate. Hydrophobic stretches, beta-sheet propensity — they form oligomers, fibrils, particulates you can't see. Subvisible particles. Those can trigger immune responses, microemboli, granulomas. FDA-approved biologics go through forced degradation studies — heat, light, agitation, freeze-thaw — to map aggregation pathways. Compounded peptides? Almost never.
Sarah: Okay, but pushback: some of these peptides have been studied. BPC-157 has animal data — rodent models of tendon healing, gastric protection. There's mechanism: angiogenic, upregulates VEGF, modulates nitric oxide. It's not pure snake oil. The peptide itself might have bioactivity.
Laura: Sure. But "the peptide" — pure, characterized, dosed correctly — is not the same as "what's in the compounded vial." That's the gap. Clinical trials test a specific drug product, manufactured a specific way, with a defined impurity profile. Change the manufacturer, change the synthesis route, change the purification — you've got a different product. That's why biosimilars require such extensive comparability exercises.
Sarah: So the policy proposal — if it happens — essentially says: we'll treat compounded peptides as if they have the same risk-benefit as approved drugs, but without the manufacturing controls that make that equivalence possible.
Laura: That's the core tension. The commenters who say "it's their body, let them choose" — they're making a libertarian argument. But they're also assuming informed consent is possible when the quality data doesn't exist. You can't consent to risks you can't measure.
Sarah: And the insurance comment — "insurance companies should deny coverage for injuries from unapproved peptides" — that's a downstream cost shift. If someone gets sepsis from endotoxin-contaminated BPC-157, or an autoimmune reaction from aggregates... the hospital bill doesn't go to the compounder.
Laura: Right. And there's a precedent. 2012, New England Compounding Center — fungal meningitis from contaminated methylprednisolone. 64 dead, 750-plus infected. That's what drove the Drug Quality and Security Act, created 503B outsourcing facilities with higher standards. But 503A pharmacies — the traditional compounders — they're still largely state-regulated, FDA inspection is reactive.
Sarah: So the verdict on the thread's claims... "broad commercial distribution of unapproved peptides" — unconfirmed, only on Reddit. "Equivalent therapeutic purity and safety to FDA-cleared biologics" — the evidence says no. FDA warning letters, testing data, fundamental synthesis chemistry all show higher variability, higher contamination risk, no aggregate characterization. "Bypassing clinical trials shifts QC to compounding pharmacies" — that's not a claim, that's a mechanical fact. And the pharmacies aren't equipped for it.
Laura: Half-right on the policy mechanics — the 2013 guidance did create a peptide list for compounding, but it was never a free pass. The rest? The community excitement is real. The chemistry is unforgiving. And the quality gap is measurable.
Sarah: One-line takeaway?
Laura: Injecting a compounded peptide without full cGMP analytics is like installing a 3D-printed titanium implant that skipped fatigue testing — it might fit, but you don't know if it'll hold.
