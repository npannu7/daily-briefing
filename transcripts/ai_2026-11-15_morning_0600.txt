## AI Coding Agents: How it actually works
Sarah: So we’ve spent the earlier parts looking at what people are building with coding agents, and now I want to pop the hood and see how the thing actually works.
Laura: Good. Watching people argue online doesn’t tell us much if we don’t know what’s happening between the prompt and the finished program.
Sarah: Right, and honestly, even people using these tools every day get tripped up by it. Someone on Reddit claimed this week that an agent wiped their entire Mac settings folder, passwords and all, just trying to clean up some test files.
Laura: Ouch. Okay, let’s start from the basics. What problem is a coding agent solving that a regular chatbot couldn’t?
Sarah: With a normal chatbot, you’re a human conveyor belt. You copy your code, paste it into a browser, ask what’s wrong, copy the answer back, run it, and paste the new error back in.
Laura: Right, it’s an open-loop system. The model spits out text with no idea whether it works or catches fire until you tell it.
Sarah: Exactly. An agent flips that by plugging the model directly into your computer’s files and commands. It reads the project, edits files, runs tests, sees the error, and tries again on its own.
Laura: Hold on. A language model is still just a math function predicting the next piece of text. How does a text predictor suddenly delete folders on a Mac?
Sarah: That’s the part that blew my mind, because there’s no magic inside the model. It comes down to a wrapper program on your computer, and a mechanism called tool calling.
Laura: Tool calling. Define that cleanly.
Sarah: Instead of writing a normal chat reply, the model outputs a specially formatted text request—basically a structured work order asking the computer to run a search or edit a file.
Laura: Wait, so the model isn’t actually running the command?
Sarah: Nope. The wrapper program on your laptop intercepts that work order, runs the command on your computer, grabs the output, and feeds it back to the model as text.
Laura: Oh, I like that. It’s like a design engineer upstairs who isn’t allowed on the shop floor. They write a work order and drop it down a pneumatic tube, and a machinist downstairs runs it on the mill and sends the inspection sheet back up.
Sarah: Yes! And if the engineer writes a terrible work order—like, delete everything in this parent folder—and the machinist downstairs obeys every slip of paper without guardrails, goodbye passwords.
Laura: That explains the Mac wipe. There was no malice, just an unguarded actuator obeying a bad command. Once you put that tube in a loop—read, edit, run, check—you’ve built a closed-loop feedback controller.
Sarah: Is that really all an agent is? A language model inside a feedback loop?
Laura: At its core, yes. We started with simple autocomplete, then chat windows for pasting files, and now the build system and automated tests act as the sensor in the loop.
Sarah: That makes so much sense, and it explains another headline from this week. Executives from Uber, DoorDash, and Airbnb said almost nobody is using personal AI agents to book rides or order food.
Laura: I saw that. Uber’s leadership said they handled roughly three hundred million trips and orders during Halloween week.
Sarah: And out of all that volume, they reported that only a few hundred transactions total came through AI agents. DoorDash and Airbnb leaders said basically the same thing, and that’s from their own company updates, not Reddit rumors.
Laura: Look at the feedback sensor. When an agent writes code, the automated tests give it a fast, unambiguous pass-or-fail signal in seconds. Booking a trip or choosing dinner has no strict pass-fail sensor—it’s all human preference, and a small mistake costs real money or annoys a customer.
Sarah: Totally. Plus, when a coding agent gets stuck, it just keeps looping until the tests pass. Which brings me to the other big topic on Reddit this week: cost.
Laura: Ah, the Goldman Sachs thread.
Sarah: Yes! Someone posted on Reddit that Goldman Sachs restricted their coding agent to engineers only, cutting off bankers and traders.
Laura: Why? What were people saying happened?

Laura: Fifty dollars for a slide deck! Why does it burn through money so fast if it’s just text?
Sarah: Because of how the model’s memory works. Every piece of text or code the model reads or writes gets chopped into tiny chunks called tokens—usually a few characters or part of a word each.
Laura: Okay, tokens are the basic unit of measurement.
Sarah: Right. And the model has no built-in memory from five minutes ago. Everything it needs to see—your instructions, every file it opened, every error, every past step—has to sit inside its context window.
Laura: Let’s nail down context window. That’s its working memory?
Sarah: Yes, its fixed-size workbench. Every time the agent takes a new step in the loop, it doesn’t just read the latest error. It has to re-read the entire workbench from top to bottom to predict the next move.
Laura: So every single cycle of the loop, you’re paying to process the whole workbench all over again.
Sarah: Exactly. If a banker asks an agent to tweak a giant spreadsheet, and it loads that file onto the bench, hits an error, and loops twenty times, you’re paying for every token on that bench on every turn.
Laura: That’s a classic scaling trap. What happens when the workbench fills up?
Sarah: Usually the wrapper program summarizes the old stuff—which loses fine details—or older things literally fall off the edge. And that’s where the biggest limitation shows up in real companies.
Laura: Let me guess. The thread about the all-AI coding mandate?
